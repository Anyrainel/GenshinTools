one-option-at-a-time workflow: what happens when several deterministic
coordinate-selection policies traverse checkpoint 38's already complete
36-node equipment table from the same source-first starting node?

It performs no new generator invocation, damage replay, evaluator call,
artifact optimizer call, rank, recommendation, guide production, or ER
calculation. The cached objective remains unreviewed and source-not-ready. The
reported paths are technical policy behavior, not equipment advice.

## Execution and ER provenance

The real default report records four trace-producing cached-policy calls. Its
authentication guard recomputes the four default policy outputs, and may be
invoked any number of times, so the report deliberately does not attest an
actual total policy-call count.

Only the real default environment attests zero fresh evaluator, generator,
damage-replay, downstream optimizer, rank, recommendation, and ER calls. An
injected test environment reports all seven counts and ER influence as `null`,
because arbitrary callbacks cannot honestly attest those seams.

Authenticating checkpoint 39 necessarily reads its ER-deferral provenance.
Checkpoint 40 projects no ER value into the policy table, the default policies
use no ER value, and no ER calculation occurs. This is different from claiming
that no ER-related field was read at all.
