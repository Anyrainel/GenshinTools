# Checkpoint 21: authenticated derived formula-fixture inventory

This checkpoint inventories the two formula fixtures already checked into the
offline lab. It keeps derived calculator assumptions separate from source
claims and does not turn technical availability into a guide result.

observations, and six unique characters. Furina and Xilonen each appear in both
scenarios. Keqing, Ineffa, Neuvillette, and Kaedehara Kazuha each appear once.

## Authentication

The adapter accepts only the two fixed fixture identities and rosters. It
authenticates supplied report objects against the current checked-in report
bytes, validates every embedded input hash against current files, resolves each
rotation back to exactly one indexed manual source record, and verifies that
all observed members belong to the independently checked 125-character released
catalog. Formula rows must belong to fixture members and cannot be duplicated
or overlap between positive and zero-default inventories.

The durable validator rebuilds both upstream formula drafts and the roster
boundary before rebuilding this report. Stale upstream or downstream evidence
cannot pass as a structurally plausible saved file.

## What this does not establish

This checkpoint performs no formula execution, damage replay, optimization, ER
calculation, or gameplay validation. It creates no source-authored plan, guide,
recommendation, rank, winner, damage claim, or source-validation claim. Both
fixtures remain withheld from guide use.
