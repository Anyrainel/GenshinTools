# 计算生成的角色攻略

2026-10-12：依据用户对原始目标的澄清。本文记录产品要求和实现缺口，
不代表攻略生成器已经完成。

## 用户要求

通过现有伤害计算，为每个角色生成以下建议：

- 该用哪些武器，以及各武器的伤害差距。
- 该用哪些圣遗物套装、主词条和副词条。
- 该怎么配队。
- 每个配队中每位角色的配装。
- 每个配队的补金顺序，以及每一步投入带来的提升。

页面主体必须是可以据此做选择的计算结论。外部攻略摘录、仓库预设、
校验报告和未选定的草稿字段不能替代这些结论。
后续开发预览仍使用不出现在应用导航栏的开发环境专用路由。

## 可复用的计算能力

| 能力 | 当前实现 | 集成时的限制 |
| --- | --- | --- |
| 武器与套装比较 | `src/domain/combat/analyzer/weaponChoice.ts` 的 `runWeaponChoice` | 固定队伍及伤害目标下的比较；武器单独排名不是全队联合最优的证明 |
| 主词条、副词条分配 | `src/domain/combat/generator/generator.ts` 的 `runGenerator` | 给定词条预算和充能/暴击约束的生成配装；不是实际背包配装 |
| 命座与武器投入 | `src/domain/combat/analyzer/analyzer.ts` 的 `runAnalysis` | 给定候选武器、命座/精炼上下限和伤害流程下的投入比较 |
| 角色替换比较 | `src/services/combat/characterReplacement.ts` | 既定队伍中的替换搜索；不能直接宣称找到了全角色最佳配队 |
| 流程与充能 | 现有 Team Analysis 的输出流程和 Energy 模式 | 攻略生成时仍需把流程、触发条件和充能要求与伤害计算绑定 |

## 建议的计算闭环

1. 定义比较条件：角色及队友命座、武器精炼范围、等级和天赋、圣遗物
   词条预算、敌人条件、候选角色/装备范围。
2. 为候选队伍建立明确的输出流程、技能次数、反应和增益触发条件，
   校验充能是否支持该流程。已有队伍预设可以提供候选，不能直接当排名。
3. 在同一个队伍和流程下比较武器、套装并生成主副词条；把最后选中的
   全队配装重新计算，确认组合后的伤害。
4. 比较队伍时保持投入条件一致。循环时间可靠时报告 DPS；没有循环时间
   时明确报告指定流程总伤害，不能把不同长度的流程直接当 DPS 排名。
5. 对每个队伍单独计算补金路径。展示起始配置、每步命座/武器变化、
   总投入和提升；区别“该预算下最强配置”与“从当前配置继续抽的顺序”。
6. 生成面向玩家的页面：队伍概览、逐角色配装、武器与套装替代选择、
   词条目标和补金顺序。计算条件及流程可展开查看。

## 验收要求

- 每条推荐都能定位到实际运行的条件、候选范围和数值结果。
- 表中的最终配装能在伤害计算器里复算；相对提升使用相同条件的基准。
- 推荐随队伍、流程和预算变化，不能把某一队伍的最优词条写成角色通用结论。
- 候选范围不足时明确范围；缺少可靠流程或充能条件时不发布配队最优结论。
- 无法计算的角色和队伍明确标记，不以预设排序、空值或报告状态补齐推荐。
- 先完成一个角色的完整闭环并核验数值，再扩展角色覆盖。

具体默认投入、候选队伍范围和生成调度方式尚未确定，实施时需要显式设定。
